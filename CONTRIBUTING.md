# Contributing

1. Pull `main` before starting.
2. Work on a branch: `feat/short-name`, `fix/short-name`, or `chore/short-name`.
3. Open a pull request. The other person reviews and approves it before it merges. Nobody pushes straight to `main`.
4. Before every commit, run `git status` and check that no `.env` file or key is staged.
5. Use fake clients (like "acme") in tests, docs, and sample data. No real client names, site URLs, or keys.
6. Keep pull requests small, ideally one piece of work each.
